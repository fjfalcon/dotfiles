# Инструкция для агентов

Этот файл читается агентами автоматически. Прочти его до того, как начнёшь
что-либо менять в этом репозитории.

## Главное: что здесь хранилище, а не источник правды

**Источник правды — локально установленные конфиги**, то есть то, что реально
подхватывают приложения:

- `~/.config/<app>/…`
- `~/.zshrc`, `~/.p10k.zsh`, `~/.vimrc`, `~/.ideavimrc`
- `~/.local/bin/…`
- `~/.mozilla/firefox/*.default-release/user.js`
- `~/.config/JetBrains/<Product><Version>/options/…`
- `~/.local/share/DBeaverData/workspace6/.metadata/.plugins/org.eclipse.core.runtime/.settings/…`

Этот репозиторий — **зеркало/хранилище** этих файлов. Он нужен, чтобы можно
было поднять машину с нуля через `install.sh` и иметь историю изменений в git.

Отсюда два правила:

1. **Когда отвечаешь про текущее состояние системы** — читай живой файл
   (`~/.config/…`), а не версию в репозитории. Версия в репозитории может
   отставать (особенно для приложений, которые синкаются копированием, а не
   симлинком — см. ниже).
2. **Когда правишь настройку** — меняй её там, где она реально действует
   (обычно это `~/.config/<app>/…`), и только потом переноси правку в
   репозиторий коммитом. Не наоборот.

## Как живые файлы связаны с репозиторием

`install.sh` использует две стратегии:

### Симлинки (правка в одном месте = правка в обоих)

Для этих путей `~/.config/<name>` — симлинк на `dotfiles/<name>`, так что
редактирование живого файла автоматически изменяет файл в репо:

- `alacritty`, `dunst`, `fontconfig`, `fuzzel`
- `i3`, `i3status-rust`, `nvim`
- `sway`, `swaylock`, `swaync`, `waybar`
- `xdg-desktop-portal`, `xdg-desktop-portal-wlr`
- `zsh/` (+ `~/.zshrc`, `~/.p10k.zsh`)
- `~/.vimrc`, `~/.ideavimrc`, `~/.config/mimeapps.list`
- `pipewire/pipewire.conf.d/30-screencast.conf`
- скрипты из `bin/` → `~/.local/bin/`

Для таких файлов репо и live идентичны по содержимому. Меняй любой из двух —
результат один и тот же, но в git нужно будет сделать коммит.

### Копирование (репо может отставать от live)

Эти приложения не работают с симлинками (или перезаписывают соседние файлы),
поэтому `install.sh` **копирует** файлы из репо в рабочие каталоги. Live
является источником правды, а репо может быть устаревшим:

- `firefox/user.js` → `~/.mozilla/firefox/*.default-release/user.js`
- `jetbrains/{laf.xml,colors.scheme.xml}` → `~/.config/JetBrains/<Product><Ver>/options/`
- `dbeaver/*.prefs` → `~/.local/share/DBeaverData/workspace6/.metadata/.plugins/org.eclipse.core.runtime/.settings/`
- `cursor/{settings.json,keybindings.json}` → `~/.config/Cursor/User/`
  (на практике Cursor использует симлинк, но приложение может перезаписывать
  файл, поэтому считай его копией)

**Рабочий процесс для этих конфигов**: редактируй в live, затем вручную
копируй в репо и коммить. Перед правкой такого файла всегда сверяйся с live —
там актуальная версия.

## Практические команды

```sh
# Сверить live с репо (для копируемых — часто отличаются)
diff -u dotfiles/firefox/user.js ~/.mozilla/firefox/*.default-release/user.js
diff -u dotfiles/cursor/settings.json ~/.config/Cursor/User/settings.json

# Применить изменения из репо к live
./install.sh              # починить симлинки
./install.sh --force      # перезаписать симлинки, указывающие не туда
./install.sh --dry-run    # посмотреть, что произойдёт

# Синк live → репо для копируемых конфигов (руками)
cp ~/.config/Cursor/User/settings.json cursor/settings.json
```

## Секреты

Никогда не коммить эти файлы (и они уже в `.gitignore`):

- `zsh/private.zsh`, любой `**/private.zsh`, `**/secrets.zsh`
- `**/.env`, `**/.env.local`

Секреты живут только в `~/.config/zsh/private.zsh` (шаблон —
`zsh/private.zsh.example`). Если нужно добавить переменную/алиас с токеном,
клади её туда, а не в `zsh/conf.d/`.

## Пакеты

Список устанавливаемых через `pacman` пакетов — `packages.txt`. Если
добавляешь в репо конфиг для нового приложения, добавь и пакет сюда
(с учётом алфавитного порядка в своей секции).

## Стиль коммитов

Короткие осмысленные сообщения в настоящем времени, на английском или
русском — как в уже существующей истории. Не коммить сгенерированные
бэкапы из `backup/`.
